# FieldCraft with NGSolve for Debian amd64, package revision r2

Install the downloaded package on a system that satisfies the dependencies reported by APT. The package manager fetches its system dependencies. The configuration step downloads the pinned CPython interpreter and NGSolve wheels from their publishers, verifies SHA-256, tests both bridge commands and solves a finite-element integral before switching the active runtime.

```sh
sha256sum -c FieldCraft-NGSolve-0.8.1-r2-linux-x64-network.deb.sha256
sudo apt install ./FieldCraft-NGSolve-0.8.1-r2-linux-x64-network.deb
```

Choose **FieldCraft with NGSolve** in the applications menu. To run your own analysis, set the script entry in your case file and open the results in the same desktop:

```sh
fieldcraft-ngsolve case "My project/example.case.json" "My project/run-01" --gui /usr/bin/fieldcraft-ngsolve-gui
```

In a new working directory, try the supplied slab model and case:

```sh
cp /opt/fieldcraft-ngsolve/bridge/samples/* .
fieldcraft-ngsolve-cli run slab.json
fieldcraft-ngsolve case slab.case.json results --gui /usr/bin/fieldcraft-ngsolve-gui
```

FieldCraft shows its desktop version as `0.8.1-ngsolve.r1`. Debian package revision r2 contains desktop source `8b495f31389512c7f599ef17b5ee3a4d0cc39bc9`, including mesh-verified catalogs, time and parameter series, and displacement display. Inspect `/opt/fieldcraft-ngsolve/BUILD.txt` for the executable hashes, compiler, solver lock, measured GLIBC requirement and the resolved native dependencies. The previous network package upgrades in place. If configuration fails, retry `sudo dpkg --configure fieldcraft-ngsolve-network` after correcting the reported problem.

## Reproduce the package with Docker

Use Linux Docker Engine, the Docker CLI, Bash, and Git on an amd64 build host. From a checkout of this packaging revision, select a fresh output directory outside the source tree and run:

```bash
bash packaging/ngsolve/linux-online/docker-build-r2.sh /path/to/release-output
```

The launcher pins the official Linux amd64 Rust 1.95.0 image on Debian 12 by manifest digest. The build image contains the committed public desktop source and packaging subtree. The launcher starts the container by its immutable image ID, so host staging cleanup during a terminal disconnect leaves the running build and its inputs intact. Cargo fetches the dependencies specified by the desktop’s `Cargo.lock`. The container generates the dependency notices with `cargo xtask licences`, verifies the pinned public Python bootstrapper, compiles both executables, validates their ELF architecture, and exercises a voltage sweep before packaging. The output includes the installable .deb, its SHA-256, Docker image ID, compiler settings, and the installed Debian package versions.

A dedicated Docker volume retains Cargo downloads and intermediate dependencies between runs. The release build recompiles both application binaries in the container. One Cargo job limits peak memory in the geometry crate. Set `FC_BUILD_JOBS` to change the number of jobs or `FC_DOCKER_VOLUME` to select another project volume. The optional `FC_CARGO_CHECKPOINT` can initialize an empty cache from the digest-verified public R2 dependency snapshot. An empty volume works with the public source and normal Cargo downloads.

The package recipe determines system dependencies from the linked ELF binaries with `dpkg-shlibdeps`, checks the highest required GLIBC symbol version, and records the exact desktop, packaging, and runtime revisions in `/opt/fieldcraft-ngsolve/BUILD.txt`. On an amd64 installation, run `packaging/ngsolve/linux-online/verify-r2.sh /opt/fieldcraft-ngsolve/fieldcraft /opt/fieldcraft-ngsolve/fieldcraft-cli` from this checkout to repeat the desktop version, external series, and deformation checks.

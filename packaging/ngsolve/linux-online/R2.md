# FieldCraft with NGSolve for Debian amd64, package revision r2

Install the downloaded package on a system that satisfies the dependencies reported by APT. The package manager fetches its system dependencies. The configuration step downloads the pinned CPython interpreter and NGSolve wheels from their publishers, verifies SHA-256, tests both bridge commands and solves a finite-element integral before switching the active runtime.

```sh
sha256sum -c FieldCraft-NGSolve-0.8.1-r2-linux-x64-network.deb.sha256
sudo apt install ./FieldCraft-NGSolve-0.8.1-r2-linux-x64-network.deb
```

Choose **FieldCraft with NGSolve** in the applications menu. To run your own analysis, set the script entry in your case file and open the results in the same desktop:

```sh
fieldcraft-ngsolve case "My project/example.case.json" "My project/run-01" --gui /usr/bin/fieldcraft-ngsolve-gui
```

In a new working directory, try the supplied slab model and case:

```sh
cp /opt/fieldcraft-ngsolve/bridge/samples/* .
fieldcraft-ngsolve-cli run slab.json
fieldcraft-ngsolve case slab.case.json results --gui /usr/bin/fieldcraft-ngsolve-gui
```

FieldCraft shows its desktop version as `0.8.1-ngsolve.r1`. Debian package revision r2 contains desktop source `8b495f31389512c7f599ef17b5ee3a4d0cc39bc9`, including mesh-verified catalogues, time and parameter series, and displacement display. Inspect `/opt/fieldcraft-ngsolve/BUILD.txt` for the executable hashes, compiler, solver lock, measured GLIBC requirement and the resolved native dependencies. The previous network package upgrades in place. If configuration fails, retry `sudo dpkg --configure fieldcraft-ngsolve-network` after correcting the reported problem.

## Reproduce the package

Use an amd64 Debian build environment with Rust, Cargo, the native FieldCraft build prerequisites, Git, Perl with JSON::PP, unzip, binutils, dpkg and dpkg-dev. Check out the exact desktop revision in a separate clean checkout. Keep the Cargo target directory outside the checkout when sharing a build cache. `cargo xtask licences` generates the complete dependency licence inventory from the locked source. The r2 recipe recognises the inventoried bytes by SHA-256. It accepts the bootstrapper from [the pinned public companion revision](https://raw.githubusercontent.com/JohannesMaierhofer/fieldcraft-ngsolve/0e3064d1bba003574f1cb3e46b0290eedc690080/packaging/debian/install-runtime.py).

```sh
packager/packaging/ngsolve/linux-online/build-r2.sh \
  desktop-checkout install-runtime.py THIRD-PARTY-LICENSES.txt \
  FieldCraft-NGSolve-0.8.1-r2-linux-x64-network.deb
```

The build verifies its Git source, compiles both executables, checks ELF architecture and versions, and runs a native voltage sweep on a two-node mesh. It resolves linked Debian dependencies with `dpkg-shlibdeps` and uses versioned symbols from both executables when declaring the libc floor. On another amd64 installation, rerun `verify-r2.sh /opt/fieldcraft-ngsolve/fieldcraft /opt/fieldcraft-ngsolve/fieldcraft-cli` to repeat the desktop and sweep checks. Debian checks these dependencies on installation. Graphics display, drivers and the external runtime have additional system requirements.
